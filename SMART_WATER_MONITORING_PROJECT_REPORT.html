1. INTRODUCTION

The Smart Water Monitoring and Complaint Management System (AquaWatch) is a web-based public utility monitoring and grievance redressal platform engineered to address challenges in urban water distribution and public utility reporting. In conventional municipality and campus settings, water leakage, contamination, pipeline damage, and supply disruptions often go unreported or suffer from severe communication delays between residents and maintenance authorities.

AquaWatch provides an integrated, digitalized platform where residents can inspect simulated real-time water quality parameters (water tank level, pH level, turbidity, and water temperature), register complaints with location and priority, receive a tracking ID (e.g., WC-00001), and monitor progress live on a visual status timeline. An authorized Administrative Portal allows maintenance supervisors to review incoming complaints and systematically update statuses across the lifecycle: Pending → Assigned → In Progress → Resolved → Closed.

Beyond core web functionality, this project implements an end-to-end DevOps automation pipeline. Source code is tracked using Git/GitHub, containerized into an optimized Docker image, validated through automated Pytest unit and integration tests, orchestrated via Jenkins CI/CD declarative pipelines, deployed with Ansible configuration management, and protected against data loss through a persistent Docker Named Volume backing the SQLite database.

2. OBJECTIVES

  • To develop a clean, responsive water utility web application using Python Flask, HTML5, CSS3, and JavaScript.
  • To implement simulated real-time water quality monitoring for key parameters (Water Level, pH, Turbidity, Temperature) with illustrative threshold categorization (Normal, Warning, Critical).
  • To provide a transparent grievance registration mechanism that assigns unique Complaint IDs and offers real-time status tracking.
  • To create an Admin Management Dashboard with session-based authentication to manage complaint workflows and inspect complaint statistics.
  • To implement Git and GitHub source code control with rigorous exclusion rules preventing database and credential leaks.
  • To containerize the application using lightweight Docker images (python:3.11-slim) for repeatable execution.
  • To build a 4-stage Jenkins CI/CD pipeline automating Checkout, Build, Pytest Validation, and Ansible Deployment.
  • To incorporate Pytest automated test coverage (13 tests) executing against isolated temporary databases.
  • To automate container deployment and port mapping (5002:5000) using Ansible and the community.docker module.
  • To implement a persistent Docker Named Volume (water_monitoring_data) guaranteeing zero data loss across container recreation.

3. ABSTRACT

Effective water management and prompt infrastructure maintenance are vital for smart communities and college campuses. Traditional water complaint systems rely on verbal communication, physical registers, or unmonitored helpdesk emails, leading to lost complaints, lack of accountability, and zero visibility into water quality trends.

The proposed Smart Water Monitoring and Complaint Management System combines a functional Flask web application with a full modern DevOps CI/CD pipeline. The user-facing module allows residents to view live water quality measurements, log categorized complaints, and track resolutions. The admin module empowers utility managers to update statuses and monitor system health. The underlying infrastructure follows a production-grade DevOps workflow: Developer code push triggers a 4-stage Jenkins pipeline which builds the Docker container (water-monitoring-ci), runs 13 automated Pytest test cases, and invokes an Ansible playbook (water-deploy.yml) inside an ansible-docker-lab container. The application container (water-monitoring-ansible) exposes port 5002 on the host and mounts a Docker Named Volume (water_monitoring_data) to /app/data, preserving complaint history permanently across container redeployments.

Step-by-Step Architecture Flow

  1. Development: Code updates, templates, and tests are prepared in the local workspace.
  2. Source Control: Changes are committed to Git with sensitive database files excluded via .gitignore.
  3. Continuous Integration (Jenkins): Jenkins fetches the latest code and initiates the declarative pipeline.
  4. Container Image Build: Stage 2 builds the standalone Docker image water-monitoring-ci.
  5. Automated Testing: Stage 3 executes python -m pytest test_app.py -v inside the container. If any test fails, deployment halts immediately.
  6. Ansible Deployment: Stage 4 copies the playbook to ansible-docker-lab and executes ansible-playbook to configure the application container.
  7. Storage Persistence: The container mounts water_monitoring_data:/app/data, ensuring SQLite database persistence.
  8. Resident & Admin Interaction: Residents access http://localhost:5002 to report issues, while admins log in to update complaint statuses.

6. MODULE 1 — USER INTERFACE & WATER MONITORING

This module delivers the resident-facing monitoring interface. It visualizes simulated water quality metrics retrieved dynamically from SQLite.

  • Water Tank Level (%): Visual bar indicating reservoir storage capacity.
  • pH Level: Color-coded gauge showing alkalinity/acidity (Optimal: 6.5 – 8.5).
  • Turbidity (NTU): Water clarity indicator with status circles (Clear, Cloudy, Murky).
  • Temperature (°C): Water temperature tracking with alert boundaries.
  • Status Banner: Categorizes overall water safety into Normal (Green), Warning (Yellow), or Critical (Red).
  • Reading History: Tabular display showing the last 20 recorded historical readings.

7. MODULE 2 — COMPLAINT REPORTING & PRIORITY SELECTION

Allows community members to report pipeline and water quality problems through an intuitive, validated web form.

  • Categories: Water Leakage, Low Water Pressure, No Water Supply, Water Quality Issue, Pipeline Damage, Overflowing Water Tank, Contaminated Water, Other.
  • Priority Levels: Radio cards with icons for Low (Minor), Medium (Moderate), High (Significant), and Critical (Emergency/Health Risk).
  • Validation: Client-side character counter (minimum 10 characters for description) and server-side validation rejecting incomplete entries.
  • Complaint ID Generation: Generates unique identifiers (e.g. WC-00001) and redirects directly to the tracking screen.

14. MODULE 9 — ANSIBLE DEPLOYMENT

Ansible automates container provisioning via the community.docker.docker_container module: 

- name: Deploy Smart Water Monitoring System
  hosts: localhost
  connection: local
  tasks:
    - name: Ensure Docker volume exists
      community.docker.docker_volume:
        name: water_monitoring_data
        state: present
    - name: Deploy application container
      community.docker.docker_container:
        name: water-monitoring-ansible
        image: water-monitoring-ci
        ports: ["5002:5000"]
        volumes: ["water_monitoring_data:/app/data"]
        restart_policy: unless-stopped

20. ADVANTAGES

  • Automated Redressal: Eliminates manual paper-based logging of water issues.
  • Data Persistence: Zero data loss across container teardowns due to Docker Named Volume.
  • Continuous Verification: Automated Pytest suites prevent defective code from reaching deployment.
  • Idempotent Deployment: Ansible playbooks ensure reproducible container states without duplicate allocations.
  • End-to-End Automation: Reduces build-test-deploy cycles from manual hours to seconds.

21. LIMITATIONS

  • Water quality metrics are currently simulated and not hooked to physical IoT hardware.
  • Demonstration authentication uses Flask sessions without production OAuth or JWT tokens.
  • Deployment demonstrated locally using Docker Engine rather than distributed cloud clusters (Kubernetes/AWS).
